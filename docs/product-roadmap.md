# 声间 Sonara：以作品效果为核心的产品规划

实施进度请查看 [连接与验收](generation-setup.md) 和 [验证记录](verification.md)。本文中的“当前原型”指规划制定时的状态。

2026-09-27 当前优先级：用户认可《靠窗那边》少拖音版片段，见 [声音基线及后续接入](sound-baseline.md)。现已接通从故事到词曲、逐字演唱与实际伴奏音符的短段创作，以及局部反馈和版本比较，见 [情绪驱动创作与真实案例](emotion-driven-creation.md)。下一步以不同故事验证听感与可重复性，再扩展主副歌作品。已认可的片段不作为其他故事的模板，也不等于本规划中的整曲、跨语言或多用户验收已完成。

日期：2026-09-26。状态：产品建议，尚未完成供应商音质评测或真实用户验证。本文件描述目标与验收条件，不代表下述能力已经实现。

## 1. 产品目标与首批用户

帮助个人创作者把想法、文字或已有音频，做成自己满意、愿意分享或实际使用的声音作品，并能通过试听和修改逐步接近创作意图。

长期形态是 AI 声音创作工作室，包含歌曲、纯音乐、配音及已有音频处理。第一条做深的场景仍是：有想法或歌词、缺少制作经验的音乐爱好者，完成一首真正唱出自己歌词的歌曲。配音面向的内容创作者作为后续独立场景验证。

中文界面，中文与英文分别评估。暂按“只有音频”同时包含两种需求规划：只上传音频开始加工；生成没有歌词的纯音乐。配音首期指单人旁白、朗读和解说，角色对话及视频口型同步后续评估。

优先级：作品符合意图且声音达标 → 修改可控 → 操作易懂 → 处理速度与成本优化。在质量达标的方案中比较效率，不用无限重试掩盖低成功率。

## 2. 用户可以从哪里开始、得到什么

| 起点 | 创作过程 | 可以交付的结果 |
| --- | --- | --- |
| 一句话、故事或情绪 | 讨论主题，提供可编辑歌词或文案，由用户决定是否继续制作 | 歌词、文案，或进一步形成声音作品 |
| 已有歌词 | 确认歌词和结构，试听演唱方向，形成完整歌曲 | 带歌唱的歌曲、对应歌词 |
| 场景、情绪、节奏和时长 | 试听配乐方向，调整发展、段落和结尾 | 无歌词的纯音乐、背景音乐、伴奏 |
| 配音文案 | 试听音色与表达，调整停顿、重音、语速和发音 | 配音、旁白，按需与背景音乐组合 |
| 录音、小样或完整音频 | 直接试听并选择目标；裁剪、降噪、分轨或混音按实际能力展开 | 改善后的音频、独立音轨或新混音 |
| 独立人声与伴奏 | 对齐、平衡、分段调整、比较 | 混音后的歌曲或配音作品 |

上传哼唱可先保存和试听；“严格按哼唱旋律编曲”需单独评测后开放。音频加工不强制填写歌词，不把自动识别出的文字视为用户原稿。提取出的声部应标注“分离音轨”，区别于原始录音或生成服务直接提供的独立轨道。

## 3. 统一创作流程

1. **说明作品目标**：用户选择歌曲、纯音乐、配音或处理音频，也可以只保留歌词草稿。只追问影响结果的信息，例如用途、语言、时长、情绪与必须保留的内容。
2. **获得可听见的方向**：歌曲用真实演唱短样；纯音乐用配乐短样；配音用同一句话的不同表达。通常提供两个有明确差异的候选。用户已有确定方向时可直接制作，避免强制多一步。
3. **形成完整作品**：把选中的方向发展为完整结果。短样延展的音色、旋律与结构一致性属于验收项；无法保持时明确提供新的候选版本，不能暗示已原样延展。
4. **指出具体问题**：在歌词、文案或波形上定位，表达“这句太急”“人声不清楚”“结尾收得太突然”。
5. **确定修改与保留内容**：展示修改范围、预期效果、可能受影响的内容；对不确定的生成改动明确说明。用户可以直接执行已清楚选定的操作，避免反复确认。
6. **试听、选择、导出**：支持同位置 A/B、原版恢复和版本保留。可选匹配试听响度，防止把“更响”误判为“更好”；导出的音量设置独立保存。

共同原则：每次音频生成和修改保存新版本；原稿和原音频保留。更新屏幕上的歌词只产生新的文字草稿，必须另行生成音频后才能更新演唱版本。

## 4. 工作台形态

首页提供四个任务入口：“写一首歌”“做一段纯音乐”“制作配音”“处理我的音频”。歌词草稿可独立保存、导出，准备好后继续生成歌曲。

工作台保留创作对话、作品画布和版本比较三个区域，根据作品类型变化：

- 歌曲画布：歌词、主歌/副歌等结构、演唱音频及可用音轨。
- 纯音乐画布：段落、能量变化、时长和音轨，不显示空歌词栏。
- 配音画布：文案句子、发音、停顿和语气，必要时显示背景音乐。
- 音频处理画布：波形、时间范围及按需展开的音轨控制。

生成中的等待、失败重试、取消和恢复应有清晰状态。修改建议必须关联当前音频版本和具体位置，不能成为与作品脱节的聊天。

## 5. 如何定义“优秀的产品效果”

共同判断是：目标用户愿意把作品用于原定用途，且能指出它符合哪些意图。不能仅凭页面可操作、音频能播放、格式参数更高或一次精选结果宣称达标。

| 类型 | 必查的作品效果 | 典型不通过情形 |
| --- | --- | --- |
| 歌词 | 表达贴合意图、语句自然、结构可唱、修改建议可选 | 擅自替换核心表达，承诺保留却丢失原稿 |
| 演唱歌曲 | 确认后的歌词被唱出、咬字清晰、旋律和情绪合适、段落完整、人声与伴奏协调 | 非预期漏词或改词、明显破音、断句妨碍理解、无故换音色 |
| 纯音乐 | 风格与用途匹配、有发展、结尾自然、需要循环时衔接成立 | 出现非预期歌唱、突然截断、明显杂音 |
| 配音 | 内容准确、发音自然、停顿和情绪合适、句间音色连贯 | 人名或数字读错、无故漏句、明显拼接感 |
| 音频处理 | 目标问题改善、重要内容保留、新增伪影可接受 | 分轨后串音严重、降噪损害人声、错位、削波 |
| 修改体验 | 修改更符合意图，保留要求得到兑现，能找回喜欢的版本 | 只变响却称改善，局部请求实际替换全曲，文字与播放版本不对应 |

将功能分为“已实测可用 / 有明确限制 / 仍在验证”，只把通过质量验收的能力作为正式入口。

必须区分以下两类修改：

- **已有音频处理**：音量、静音、裁剪、对齐和组合。可用明确时间范围及非破坏性处理控制影响范围。
- **重新生成内容**：改唱词、换旋律、改变演唱、重新配器。模型提示中的“保留”不等于结果保证。需要核对人声、旋律和段落外音频；不支持局部保留时提供明确标注的重生成版本。

## 6. 先做真实音频评测，再扩大界面范围

首轮建议准备 24 个原创或已获使用授权的简短任务：8 个歌词演唱任务（中文、英文各 4 个）、4 个纯音乐任务、6 个配音任务（中文、英文各 3 个）、6 个已有音频处理任务。歌曲短样测试之后，还需验证完整作品及短样延展，不能只评副歌片段。

每类能力尽量比较两个可正式接入的候选方案。所有候选使用相同创作目标、相同源素材及一致的重试上限，允许做必要的接口适配，并记录适配内容。每个任务至多尝试三轮，保留全部结果和失败记录，不只展示精选结果。

试听采用隐藏供应商名称、随机顺序及合理的监听响度控制。由目标用户评价意图和使用意愿，熟悉音频的人协助核查音质、歌词和范围保留。语音识别只辅助核对唱词，最终需人工听辨。

记录：首轮可用率、三轮内可用率、每次修改是否改善、重要内容保留情况、形成可用作品的总耗时、总费用、人工介入位置。费用包含被淘汰的候选和重试；速度报告中位数及较慢任务，不用最快案例代表整体表现。

暂定工程决策线：各能力类别、各语言分别达到至少 80% 的测试任务在三轮内获得目标用户评分不低于 4/5 的可用结果，且被接受的作品没有重大内容错误。整数任务数向上取整。该门槛仅用于初轮筛选，样本小，不代表已证明市场需求或生产稳定性。

真实用户验证延续既有歌曲方案：6 位音乐爱好者，中文、英文各 3 位；至少 4 人完成愿意分享的歌曲，至少 4 人完成两次有效修改并保留重要内容，至少 3 人在一周内自愿继续使用，两种语言均有成功案例。配音进入下一阶段时另招募对应创作者，不能用歌曲用户的成功替配音场景背书。当前尚未招募或执行这些测试。

## 7. 分阶段交付与进入条件

| 阶段 | 主要工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：声音效果验证 | 准备基准素材；评测歌词演唱、纯音乐、配音及分轨；形成能力清单 | 获得真实可听结果、清楚的限制与成本；至少歌曲主路径通过初步评测 |
| B：第一版真实歌曲产品 | 想法/歌词输入、真实演唱方向、完整歌曲、歌词与音频版本绑定、比较与导出；同一能力达标后开放纯音乐 | 用户自己的歌词真正被唱出；完成保存、重开、播放和导出的完整流程；推进六人验证 |
| C：完善已有音频 | 音频直接导入、真实分轨、局部平衡与裁剪、源素材与版本关联 | 在真实小样上改进用户指出的问题，保持轨道对齐和可接受音质 |
| D：独立配音体验 | 单人配音、逐句试听与重生成、发音和停顿修正、配乐混合 | 配音目标用户能完成可使用的作品，并通过独立场景验证 |
| E：更精细的创作 | 局部重唱、保旋律改词、稳定音色、哼唱编曲、角色对话等 | 逐项通过真实音频测试后开放，允许不同能力分批上线 |

A 阶段可同时评估几类能力，但 B 阶段集中打通歌曲。若歌曲音质未达标，应继续验证或调整可承诺的范围；不能以配音或器乐演示代替歌曲成功。阶段顺序可根据真实用户结果调整，不先承诺固定发布日期。

首版暂不扩展社区、交易市场、专业 DAW 的全部功能和实时多人协作。

## 8. 能力来源与已有研究的作用

底层按能力分别接入：文字创作、歌曲与演唱、纯音乐、语音合成、音频识别与时间对齐、分轨与处理。用户面对统一作品流程；开发时保留替换服务的空间。优先选实际效果最好的可用能力，不以自研或单一供应商为前提。

截至本次查阅，官方文档提供了以下可供评测的路线，尚未对其作真实调用或音质背书：

- ElevenLabs 的音乐接口有包含歌词、风格和段落时长的创作计划，可作为指定歌词演唱候选；中文效果、咬字、延展及局部修改的实际表现需评测。[官方创作计划文档](https://elevenlabs.io/docs/eleven-api/guides/how-to/music/composition-plans)
- ElevenLabs 的语音合成面向文字到口语音频，可作为配音候选；与歌唱分别验收。[官方语音合成文档](https://elevenlabs.io/docs/overview/capabilities/text-to-speech)
- Stability AI 提供以输入音频和文字说明进行音频转换的接口，可作为音频再创作候选；不能据此承诺旋律、演唱或所有未选中内容完全不变。[官方接口文档](https://platform.stability.ai/docs/api-reference)
- StemDeck 的研究可用于分轨任务、处理进度、多轨试听和导出流程；分离出的声部可能有串音。[项目仓库](https://github.com/stemdeckapp/stemdeck)
- Antra 的研究可用于来源记录、去重、归档和多来源接入设计。我们主要借鉴组织方式；直接复用代码需核对其 Elastic License 2.0 的具体限制。[项目仓库](https://github.com/anandprtp/Antra) · [许可](https://github.com/anandprtp/Antra/blob/main/LICENSE)

正式选型还应核实 API 可获得性、账户套餐、允许的使用方式及输入素材政策。先记录单首达标作品成本，再确定定价；本规划不指定付费方案或产生购买。

## 9. 支撑作品质量的基础设计

- **原始素材与派生关系**：保存原音频、用户文字、生成结果、分离音轨和最终导出之间的关联，以及处理来源和设置。
- **文字与音频绑定**：每个生成版本引用当时的歌词或文案快照；当前文字修改后显示“尚未生成对应音频”。有可靠时间戳时才显示逐句跟随，不伪造歌词同步。
- **版本与保留要求**：保存修改意图、目标时间段、要求保留的内容、实际执行方式和父版本。用户可恢复旧版或从旧版继续修改。
- **任务与存储**：采用服务端保护密钥、异步任务和可靠音频存储；处理中断、重试和重复请求不应丢失项目或重复触发未知费用。用户能够清楚知道哪些素材会传给外部处理服务。
- **音质链路**：保存服务返回或用户上传的原始质量；试听副本与最终文件分开。最终导出优先支持源质量的 WAV 与便于分享的压缩格式，记录实际格式；提升采样率或位深不能恢复已丢失的信息。
- **音量与导出**：检测过载、避免无提示限幅，按用途给出适当响度处理；导出后核对时长、声道、内容和保存成功。

## 10. 从当前原型继续的第一批工作

当前原型已经提供歌词编辑、器乐演示、音频导入、部分音轨控制、版本比较和本地保存。尚无真实歌词演唱、配音生成、自动分轨或真实语言模型服务。当前 22.05 kHz 的处理链路用于体验验证，应在正式音质评测前调整，保留原始质量。

下一批工作建议按以下依赖顺序落实：

1. 固定首轮中英文歌词和原始音频测试集，列出希望听到的结果及必须保留的内容。
2. 评测可正式接入的真实演唱方案，记录唱词准确性、可用率、时长和成本。
3. 增加受控的服务端任务与音频存储，接入通过评测的歌曲能力。
4. 实现歌词快照与音频版本绑定，完成“输入自己的歌词 → 真实演唱 → 完整歌曲 → 导出”的验收。
5. 在实际用户测试中验证修改体验，再依阶段计划接入分轨和配音。

本轮交付是产品规划文件；没有新增界面、接入供应商或执行付费生成。既有验证文档继续记录原型实际状态，不把未来规划计入已完成能力。
