# 产品定位与首轮验证手册

更新：已提供候选音乐服务接入口，真实账户与音质评测尚未完成。可按 [生成连接与验收](generation-setup.md) 使用当前歌词生成入口；未生成真实演唱之前，仍不得计入歌曲成功或发音评分。

## 定位与待验证假设

为有想法和歌词、但缺少制作经验的音乐爱好者提供一个一起讨论、试听和修改的制作伙伴，帮助他们完成愿意分享的歌曲。覆盖中文、英文创作，界面先中文。

核心假设：用户能以日常语言表达意图；具体方案和可逆版本比较能帮助他们把音乐改得更满意；完成后仍愿意回来创作。首轮研究不能以六人样本证明市场规模或长期留存。

## 招募与准备

招募 6 位有歌曲表达想法、不会熟练制作的爱好者，中文和英文各 3 位。使用 ZH-1 至 ZH-3、EN-1 至 EN-3 编号。每人带自己的想法或歌词；如已有音频，优先使用。当前未招募或联系任何人。

向参与者说明：当前工作台的对话是规则演示，器乐例子为预制原创示例；完整演唱生成和自动分轨需外部制作。征得研究记录及音频使用的同意，允许随时停止。未获同意的音频不外传。工作台不会替研究员上传、联络或采购服务。

准备步骤：创建以参与者编号命名的独立作品；让参与者输入自己的想法与歌词；准备已获使用授权的小样，以及人工或外部工具处理的渠道。真实演唱作品未准备好时，只验证编辑流程，把歌曲完成度和发音项标为未评估，不计为成功案例。

## 首次测试（建议 45–60 分钟）

1. 让参与者说明想写给谁、表达什么，以及最希望保留的内容。记录原话，避免替其决定目标。
2. 试听两种方向或自带参考，描述喜欢和不喜欢的原因。预制器乐只用于讨论声音，不作为“根据其歌词生成”的结果。
3. 用人工辅助或外部工具完成一首带演唱的作品，记录工具名称、提示、尝试次数、耗时、费用和人工介入。导入工作台作为新版本。
4. 请参与者说出两处具体不满，分别执行“意图 → 方案 → 确认 → 修改 → A/B”。不要预先告诉其应该选哪一版。
5. 逐次询问：改善的是哪里？是否只是更响？重要内容是否保留？有无新的问题？记录未成功的尝试。
6. 请参与者自行选择最终版本并导出。询问是否愿意分享完整歌曲，以及希望分享给谁；不要求实际公开发布。
7. 在验证页填写观察。发音、断句为 1–5 分；未听到演唱就保持未评估。费用统一人民币，外币费用记录换算依据于备注。

## 一周观察

观察首次测试后第 1–7 天内，参与者是否自愿继续修改或开始另一首歌。工作台不会自行发送提醒。任何访谈回访与主动创作须区分记录；研究员催促的操作不能算自愿返回。同一天再次打开不计入此轮回访门槛。

## 决策门槛

- ≥4 人完成愿意分享的完整歌曲。
- ≥4 人完成至少两处修改，确认具体问题改善且重要内容保留。
- ≥3 人在首次测试后 1–7 天内自愿回访。
- 中英文组各至少 1 人同时满足作品分享与可控修改标准。

满足门槛后，把最频繁的有效修改需求列为下一版优先项；若主要失败来自生成质量，先做供应商音频评测；若主要失败来自难以表达或比较，先改交互；若缺少回来继续创作的动机，重新检视受众和使用场景。

## 技术与真实音频证据

`validation/audio/01-original.wav` 与 `02-chorus-refined.wav` 是原创合成器乐案例。后者仅增强副歌 43.636–65.455 秒的鼓、贝斯和和声音量；主旋律不变。`comparison.json` 记录段落外逐样本差异数应为 0，段落内应有实际差异。

这些音频可证明本地音频修改有效，不能证明带演唱生成、自动分轨或最终发行质量。需要补充中文和英文真实歌曲案例后，才能评估这几项能力。

## 交付记录

每位参与者：原始想法与歌词、原始音频、两次以上的修改意图/方案/前后音频、保留要求、最终选择、耗时/尝试/费用/人工帮助、回访日期与主动性。研究表通过验证页导出 CSV；音频通过作品页单独导出，存于受控本地目录。

## 后续能力接入建议

先用同一组已获授权的中英文测试音频比较候选服务，不按宣传选供应商。逐项测试中文咬字、英文重音、改词保旋律、局部修改不影响其他段落、分轨串音、延迟与费用。为每项标注“实测可用 / 有限制 / 不可用”，保留输入、输出和版本。

本轮没有对任何外部音乐服务作真实 API 调用，也没有消耗生成费用。API 供应商、服务端部署和账户体系留待真实工具评测之后确定。
