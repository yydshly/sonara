# 产品主线整理与体验审查

2026-09-26。目标：普通创作者从自己的想法出发，始终知道正在制作哪首作品、这一轮会改变什么，以及下一步怎么听、怎么改、怎么带走。

## 结论

用户感到半成品是准确的：项目仍是能力验证原型。局部模型控制、可播放结果和测试通过，并不能证明它能稳定做出令人满意的完整歌曲。这次修复入口、项目归属、情绪依据和版本交付的断裂，没有将声音质量问题标记为完成。

3. **试听修改：原先有真实 A/B，但任务分散。** 可定位歌词、比较 V2/V3 和保留历史是已有优点；新旧实验使用不同入口，用户需要理解工具结构。现在个人创作使用四个明确阶段，情绪目标随版本保存、传入后续修改。完整示范中的逐字唱法工具仍是独立能力，尚未假称已接入所有个人作品。状态：主流程已整理，生成与声音能力仍受限。

4. **选定与导出：新增集中的版本交付。** 从实际试听的 A 或 B 选定版本，集中下载演唱、人声、伴奏、歌词、MIDI 和词曲数据；刷新保持选定版本。旧项目没有独立情绪字段时明确说明，不补造记录。状态：已核对原有真实作品 V2 的导出身份。

- 108 项自动测试通过，包括目标格式验证、重复请求变化拒绝、创作依据冻结、词曲模型参数传递、导出与后续版本继承，以及原有生成取消、失败恢复、音频保护。
- 浏览器实际验证新想法不显示旧作品；导航、打开旧作品、A/B、导出页、返回与刷新可用。导出页选择 A/V2 后刷新仍为 V2。
- 情绪草稿写入后刷新保持；测试输入随后清空，原想法原文保留。没有提交测试创作或制造听感评分。

## 什么时候才算产品成立

下一阶段按用户结果验收，而非按控件数量验收：

1. 从个人故事和情绪方向出发，生成具有连贯主歌、副歌、桥段和结尾的原创整曲词曲；不能将四句循环或固定样本当作完成整曲创作。
2. 同一歌词与旋律可以比较不同演唱表达，至少有一个结果让创作者认为咬字清楚、音色自然、情绪符合内容。气声参数有变化不等于通过。
3. 对听到的具体问题提出修改后，能改善目标问题，同时保留重要内容；以真实 A/B 和创作者判断为依据。
4. 在同一个项目中走完创作、确认、演唱、修改和交付，带走所选版本及对应歌词、乐谱与伴奏。

优先解决完整词曲生成和声音表现上限，再把已验证的局部唱法控制接入个人作品；不继续用新增说明面板替代音乐效果。英文演唱、通用配音、多声线、自动分轨与专业编配仍按真实能力逐项验证。
