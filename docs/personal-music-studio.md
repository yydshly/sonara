# 我的音乐工作台 · 2026-09-29

## 产品主线

目标是让没有制作经验的人，也能从自己的经历和情绪出发，完成愿意保留和分享的原创音乐。新入口是 `studio.html`，发布地址为 `/studio/`；此前的按谱实验保留在 `compose.html`。

1. **想法与情绪**：选择歌曲或纯音乐，写故事、具体细节、起始情绪、情绪展开与余韵。风格、节奏、声音、目标时长和不希望出现的内容可以独立调整。
2. **歌词与表达**：用已登录的 Codex 或 MiniMax Code 生成候选歌词，也可以自己写词。候选稿不会覆盖原稿，用户先采用或编辑，再明确确认用于音乐生成。纯音乐跳过歌词。
3. **生成与试听**：固定本次歌词与创作要求，交给 MiniMax Code；支持本机自动调用，也支持复制任务、在自己的工具中完成后导入真实音频。
4. **继续打磨**：试听不同版本，分别记录情绪和自然度，标记最喜欢的一版。点击“调整方向，再做一版”会把已保存的听感带入修改要求；原音频与生成依据保留。

一次成功的创作不是“模型返回了文件”，而是用户听过之后认为作品符合表达，并愿意再听。平台不会自动给作品打优秀分，也不把演示音频当作新生成结果。

## 模型分工与控制

| 内容 | 当前实现 | 验证状态 |
| --- | --- | --- |
| 原创歌词 | Codex 非交互执行，严格 JSON 结果 | 已用真实账户生成《再坐一会儿》候选稿，并在界面采用、保存、准备任务 |
| MiniMax 歌词 | MiniMax Code 非交互执行，同一歌词结构 | 适配与失败处理已测试；本机 CLI 0.5.8 已安装，实际检查提示需要登录 |
| 整曲音乐 | MiniMax Code 调用其账户可用的音乐工具，交回真实 MP3/WAV | 任务与文件验证已实现，等待登录后验证音乐工具权限、额度及音质 |
| 音频交接 | 复制完整任务 → 用户执行 → 导入对应音频 | 支持本机和静态网页版 |
| 按谱合成 | 原有 DiffSinger、声库、乐器流程 | 保留为独立实验，不作为 MiniMax 输出 |

“MiniMax Code 入口可用”仅表示命令能执行，不表示已经登录、具有音乐工具或账户额度。Code/Token Plan 与音乐能力不作等同承诺。生成目标时长、歌词保留和情绪走向是请求约束，是否实现必须听实际音频。整曲重新生成可能改变旋律、人声与编配；当前没有承诺局部修改且其他声音完全一致。

## Windows 局域网接入

MiniMax Code 在另一台 Windows 电脑时，可以从本机工作台“生成连接”开启局域网任务端口，下载连接包带到另一台电脑运行。支持远程歌词候选稿与音乐音频回传；账户留在生成电脑，创作记录留在平台电脑。详见[连接步骤与边界](windows-lan-generation.md)。当前协议与模拟回传已测试，真实两台电脑及音乐结果待验证。

## 本机接入

网页与服务使用原生 Node.js。本轮本机验证使用 Node.js 24.19.0，MiniMax Code 0.5.8 已实际安装并验证命令入口；连接检查返回明确的未登录提示，尚未产生新的 MiniMax 音乐。MiniMax Code 是独立的可选工具，按其官方要求使用 Node.js 22.19+ 或支持的 24–26 版本。为复现本轮适配，可安装已核查的官方版本：

```sh
npm install --prefix .local/minimax-code @minimax-ai/code@0.5.8
node .local/minimax-code/node_modules/@minimax-ai/code/cli.js login
npm start
```

国际区账户按官方说明在 login 后追加 `--region global`。登录由用户在自己的账户中完成。已安装在本项目 `.local/minimax-code` 下的入口会自动发现；否则使用命令路径中的 `mcode`。自定义安装可配置 `SONARA_MCODE_BIN`，Node 启动的入口可另设 `SONARA_MCODE_ENTRY`；不把账户凭据填写到网页或提交到仓库。

适配器采用官方 `mcode exec`：stdin 输入、独立任务目录、JSON schema 输出、`smart` 权限、有限步骤与超时。只有成功的执行状态、匹配的任务 ID、任务目录内的实际音频均通过验证，才把版本记为完成。CLI 请求权限确认、工具不可用、超时或返回不明时，保留记录并显示待核查，不自动重试。

参考：[MiniMax Code 官方仓库](https://github.com/MiniMax-AI/minimax-code)、[MiniMax 自动化接口](https://agent.minimax.io/docs/cli/automation)、[MiniMax 音乐 API 说明](https://platform.minimax.io/docs/api-reference/music-generation)、[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)。本轮使用 Code 间接调用，未另接音乐 HTTP API。

## 保存与部署

- 本机：草稿、任务、候选歌词和音频保存在 `.local/studio/`，网页与管理接口只监听本机回环地址；可主动开启独立的局域网任务端口。刷新页面可以继续；服务重启不会重复提交中断任务。
- 网页：GitHub Pages 使用 IndexedDB 保存当前浏览器的项目与音频，不上传到公共仓库。可以写词、准备任务、导入音乐、试听比较、记录反馈、下载音频。
- 网页尚无云端生成后台，不能借用访问者本机账户自动执行模型。需要自动生成时，打开已启动的本机工作台。
- “导出档案”保存故事、歌词与版本记录；音频需要逐版下载。导入档案会建立新的草稿，不会把没有音频文件的旧记录伪装成可播放作品。
- 浏览器存储可能被清理，应导出重要作品。当前没有跨设备同步、多用户账户与云端任务队列。

任务采用固定快照与请求去重；保存失败不能进入成功状态；取消后晚到结果不能覆盖状态；已完成版本不能被再次导入覆盖。本机 MP3/WAV 有结构、大小、时长、路径与散列检查；浏览器导入需通过真实音频解码。

## 本轮验证证据

- 自动化测试覆盖草稿冲突、任务快照、重复提交、失败/取消/重启、非法音频、路径限制和音频范围请求。
- 本机界面完成真实 Codex 候选稿的生成、采用和音乐任务准备。
- `/sonara` 子路径发布包在浏览器中完成纯音乐任务、已有公开 MP3 的导入、刷新后恢复与播放、听感保存、将反馈带入下一版。这个音频仅用于验证导入流程，未冒充新生成作品或用户认可。

## 下一步的质量验证

先用同一套真实创作内容验证两种歌词模型和 MiniMax 音乐工具，记录成功率、等待时间、处理成本以及实际可用控制。至少包含温暖叙事歌曲、具有节奏张力的歌曲和纯音乐。重点听歌词顺畅、段落发展、句尾长度、演唱自然度、情绪转折与伴奏平衡，再决定默认方向。

接通音乐账户只是第一步，不能据此宣称声音质量已解决。六位目标用户与一周回访的验证计划仍保留；配音、分轨、云端账户和专业混音继续作为后续范围。
