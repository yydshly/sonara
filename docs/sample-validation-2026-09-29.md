# 用样例驱动创作验证 · 2026-09-29

本轮实际生成了六份歌词，并为其中三份再次调用 Codex 进行定向文字修订。另有两个原创纯音乐方案。全部故事是为本项目设计的虚构场景，没有读取或公开用户已有作品。

## 实际发现与处理

1. 《到家再说》的“装得响亮”不够自然。通过平台的修改要求再次生成，改为“不用再装作没事”，其余故事、动作与主副歌保留。
2. 《最后一班校车》的一句副歌太长，不利于 128 BPM 方向的可唱性；原结尾“喊一声见”也别扭。模型把长句拆成两个短乐句，将结尾改为“下次有空，群里喊一声”。是否唱得自然仍需真实演唱验证。
3. 英文样例出现 `loading ground`、含糊的换钥匙表达和不自然的换挡说法。第二轮改成日常英语，同时保留核心副歌与河边告别的场景。

以上是助手的**文字检查**，不是用户评价或试听结论。界面保留原稿、修订原因及新稿。原始任务、模型输出和执行记录留在本机；公开样例仅导出预先设计的虚构场景及其模型候选稿，不导出后续用户编辑或日志。

这些发现已补入下一次歌词生成的检查要求：口语自然、快节奏句长、英文搭配与重音。是否能降低新故事中的问题，需要下一轮验证，不能由这三个修订案例推断稳定性。

## 进入产品后的用法

在工作台打开“灵感与样例”，可以筛选歌曲/纯音乐、随机挑方向、查看词稿和情绪变化，再复制成自己的作品。也可以只复制故事，重新让模型写词。随机功能从八个完整方向中抽取，遍历一轮前不重复，不把不相关的人物与场景机械拼接；它本身不触发新的模型调用。

网页版同样可以查看和复制样例，作品保存到当前浏览器。本机版另可调用歌词模型。复制不会覆盖原项目，不会复制虚假的生成记录或预先勾选歌词确认。

## 下一步要验证的声音问题

先选一首快歌、一首克制叙事和一首纯音乐，确认歌词后用真实音乐工具生成；记录字词清晰度、句尾长度、段落发展、动态层次、人声与伴奏平衡。保留原稿和每次请求，从具体问题驱动下一版，而不是继续扩大样例数量。

本机复现命令（明确调用才执行，CI 不会运行生成）：

```sh
node scripts/generate-studio-samples.mjs --generate
node scripts/generate-studio-samples.mjs --refine
node scripts/generate-studio-samples.mjs --export
```

本轮清单在 `.local/sample-runs/first-eight/`。请求标识先保存，重跑不会重复提交已经成功的任务；检测到样例被用户修改时会停止覆盖。公开文件是 `dist/studio-samples.json`，每份候选稿包含模型来源与生成时间。
