# 两台 Windows 电脑的局域网创作

平台电脑保存故事、歌词、任务和音乐版本；另一台电脑使用自己的 MiniMax Code 登录，领取明确提交的任务并回传结果。支持歌词候选稿和整曲音乐。无需把 MiniMax 密码或密钥交给平台，也不需要在生成电脑开放远程控制。

## 第一次连接

1. 在平台电脑启动声间，打开本机 `studio.html`，进入左下角“生成连接”。
2. 在“让另一台电脑，负责生成”选择当前 WLAN 或以太网的 IPv4 地址。不要选择 VMware、WSL 等虚拟网卡。点击“开启局域网连接”。
3. 下载 Windows 连接包，复制到已登录 MiniMax Code 的电脑，先解压到自己的目录。
4. 生成电脑需要 Node.js 24 LTS，以及可用的官方 MiniMax Code 命令行。先在它的终端确认 `mcode --version`，完成 `mcode login`；已有登录可以直接使用。只有 MiniMax 桌面界面时，需要另行安装官方命令行，不能假设桌面登录已自动共享。
5. 双击 `start-worker.cmd`，保持窗口打开。回到平台查看“另一台电脑已连接”。第一次配对只检查命令入口，不会自动调用音乐工具。
6. 写歌词时选择“MiniMax Code · 另一台电脑”；确认歌词并准备音乐后，在“在哪里生成”选择“另一台电脑”，再点击生成。真实结果回来后才能试听。

自定义安装可通过生成电脑的 `SONARA_MCODE_ENTRY` 指定 `cli.js` 完整路径，或 `SONARA_MCODE_BIN` 指定可执行程序。本地 npm 安装和 Windows 全局 npm 安装中的官方入口可自动识别，避免把 `.cmd` 当成原生程序执行。

## 网络与保存

- 平台网页、完整作品库和管理接口继续仅监听 `127.0.0.1`。点击开启后，另一个端口 `4176` 只绑定选中的私人局域网地址，只提供任务领取和结果回传。
- 另一台电脑主动连接平台。需要两台保持在线；不需要路由器端口转发。Windows 防火墙拦截时，仅允许私人网络中的必要访问，不要开放公共网络。
- 当前使用 HTTP，因此只用于受信任的私人局域网，不适合公共 Wi-Fi 或公网。下载包的 `connection.json` 是本次连接的随机配对凭证，不是 MiniMax 密钥；不要公开、转交无关人员或提交仓库。
- 一次只配对一台生成电脑。关闭连接或平台重启会撤销旧凭证，重新开启后需要重新下载包。默认不开启局域网端口。
- 生成电脑将任务、执行结果、实际音频保存在解压目录下的 `.local/remote-worker/tasks/`；平台接收的成品保存在自己的 `.local/studio/`。两处资料均不自动上传 GitHub。
- GitHub Pages 仍是静态网页，不能直接借用这个局域网连接。请在本机工作台配对和自动生成；网页版继续支持任务交接和手动导入。

## 断线与版本保护

任务在领取前就保存固定的歌词和情绪要求；另一台电脑领取后，平台保存领取凭证，生成电脑也先写入本机记录，再调用模型。每次只能执行一个远程任务。

回传确认丢失时只重传已经保存的结果；不会重新调用模型。相同歌词结果或同一音频散列重复回传可以确认成功，其他内容不能覆盖原结果。原始草稿不会被歌词候选稿自动替换。

生成中的电脑超过 90 秒没有联系，或任务超过等待上限，平台标记“结果待核查”，不会把任务自动交给另一实例。取消后晚到的结果不覆盖状态。生成程序崩溃后不重新执行已经开始的任务；用户应先检查该电脑上的文件，可以将已有 `song.mp3` / `song.wav` 手动导入一个允许接收文件的版本。

“停止等待”或关闭连接不能保证已发出的外部音乐请求立即取消，需到 MiniMax 核查。模型需要人工权限确认、缺少音乐工具或账户额度时，连接程序会停止该任务并保留说明。账户可用性与音乐质量必须用真实任务确认。

## 验证范围

本轮自动化验证使用独立临时目录和模拟生成器，覆盖真实 HTTP 领取、歌词与音频回传、取消、断线超时、配对撤销、重启不重复生成、结果确认丢失后的重传、非法音频与越权请求。模拟测试音频不是新生成的音乐，不作为用户作品发布。

本机页面已加入配对步骤、地址选择、连接包下载、在线状态和生成位置选择。用户的另一台 Windows 电脑尚未实际配对；真实 MiniMax 登录、音乐工具可用性和音质仍待现场验证。

本轮共 168 项自动化测试通过；统一入口及 `/sonara` 发布包构建通过。Windows ZIP 已实际解压，内部模块可以加载并检测到已安装的 MiniMax Code；此检查没有发起音乐生成。
