# 词曲 → 歌声 → 混音：逐句创作试验

入口：运行声间后打开 `/score-trial.html`，或点击工作台顶部的「词曲试唱」。

2026-09-26 已完成 A、B 两版真实合成演唱。模型加载后的五句合成共用时约 83 秒（四句原词、一句改词；不含环境准备和下载）。最终混音峰值约 0.712，无削波，修改区间外逐样本一致；这不是主观音质评分。

本次使用原创中文副歌《晚风来信》，80 BPM、C 大调、4/4 拍，8 小节，音乐部分 24 秒，文件保留到 26 秒。不是整曲生成服务；先明确编写歌词与 32 个逐字音符，再通过本机 DiffSinger 推理生成演唱，最后与独立合成的电钢琴、贝斯、鼓伴奏组合。

## 在网页继续创作

1. 在「B · 继续创作」选定要接着修改的版本，选择四句中的任意一句。
2. 输入 8 个汉字，点击「检查歌词与拼音」。多音字可逐字改为声库支持的不带声调拼音。
3. 确认生成，完成后自动保存为新版。A 自动指向修改前的版本，B 为结果；两者可在同一播放位置切换，也可只听人声。
4. 继续改另一句，前一次的成果会被继承。历史记录可选旧版继续分支创作。下载链接对应当前正在试听的版本，含混音或人声、歌词与带新歌词的 MIDI。

生成在本机执行，可取消；失败或服务中断不发布未完成音频。刷新页面可以继续查看任务，重启服务不会自动重跑中断任务。任务记录、完整歌词、拼音、结果与音频保存在 `.local/score-edits/<版本 ID>/`。模型、原始 A/B 文件和原始逐句音高数据仍需保留，不应在已有修改版本时随意重建示例基线。

网页已实际生成两次连续修改：第二句「把思念写成一封信」，再将第四句改为「让晨光带我找到你」。两次合成分别约 11.96 秒与 11.42 秒（本机实测，不含首次环境准备，不保证其他设备速度）。后一次保留前一次第二句的音频。最终文件均为 26 秒、44.1 kHz / 24 bit；对应修改区间外逐样本相同，音高控制曲线保持一致。

逐句新演唱按当前句的人声电平做有限增益匹配，再与原伴奏合并；只替换选定的六秒，不重算其他片段。音高控制一致与音频边界检查不能代替对实际音准、咬字和衔接自然度的试听评价。

## 两版比较

| 项目 | A 版 | B 版 |
| --- | --- | --- |
| 第 2 句 | 把心事唱给星星听 | 把想念藏进晚风里 |
| 乐谱 | 相同的音高、起点和时长 | 完全沿用 A 版 |
| 音高控制曲线 | 根据 A 版乐谱预测 | 复用 A 版第 2 句的曲线 |
| 发音 | 根据原词预测 | 根据新词重新预测 |
| 第 1、3、4 句 | 原版人声片段 | 复用原片段，不重新合成 |
| 伴奏 | 独立伴奏音频 | 同一份伴奏音频 |

改动区间为 6–12 秒。渲染脚本要求区间外的混合音频逐样本相等；区间内必须出现音频差异。两版使用同一人声增益，不分别自动归一化。

这说明在保留乐谱和独立音轨的前提下，可以尝试局部改词。它不代表对任意已混合的 MP3 都能保持旋律改词，也不证明音色、咬字或情绪已经达到成品要求。

## 文件与复现

试听文件与词曲位于 `dist/score-trial/`：

- `score.json`：逐字歌词、拼音、音符、节拍位置、时长与和弦。
- `melody-A.mid` / `melody-B.mid`：标准 MIDI，含速度、拍号、音符和歌词事件。
- `lyrics-A.txt` / `lyrics-B.txt`：两份原始歌词。
- `accompaniment.wav`：伴奏；`keys.wav`、`bass.wav`、`drums.wav` 为独立音轨。
- `melody-guide.wav`：器乐旋律示范，明确不含演唱。
- 成功渲染后产生 `song-A.wav`、`song-B.wav`、`vocal-A.wav`、`vocal-B.wav`，均为 44.1 kHz / 24 bit。
- `result.json`：实际渲染状态、处理时间、音频峰值、修改区间、文件散列。只有 `status=rendered` 才表示演唱已经完成。

生成词曲和伴奏：`node scripts/create-score-trial.mjs`。

本机试验环境隔离在 `.local/score-trial/`，不会上传歌词与声音，也不依赖在线音乐账户。模型不放在公开静态目录。用该目录下的 Python 环境执行 `python -X utf8 scripts/render-score-trial.py` 可渲染歌声。逐句缓存保存于 `rendered-phrases/`；缓存只针对本次固定模型与推理设置，不是通用缓存服务。

下载脚本只负责从作者 GitHub 和 PyPI 获取文件。Python 依赖版本保存在 `.local/score-trial/requirements.lock`，声库包的来源和本机 SHA-256 保存在同目录 `*-download.json`。ZIP 经 CRC 检查后解压，Python 包经 PyPI SHA-256 校验后在隔离环境安装。

## 采用的工具与边界

- 歌声：[Ria / 狸安](https://github.com/RibosomeK/RiaDiffSinger)，声音来源与作者为 RibosomeK。本次采用 v0.4 lynxnet 与作者配套的音高、声码器包；按作者要求为输出署名。
- 推理：[diffsinger-utau](https://github.com/bingcheng1998/diffsinger_utau)，MIT。使用其时长、音高、表现参数、声学模型、声码器流程；适配代码位于本项目渲染脚本中。
- 基础项目：[OpenVPI DiffSinger](https://github.com/openvpi/DiffSinger)。此处使用导出的 ONNX 模型，在 CPU 上执行。
- 配套声码器的说明声明权重采用 **CC BY-NC-SA 4.0**，来源为 [DiffSinger 社区声码器](https://openvpi.github.io/vocoders/)。本次为本机路线试听实验；正式商业产品接入需另行核实授权或更换组件，不把这套试验模型作为已确认可商用的供应链。

当前页面支持这段指定乐谱的中文等字数逐句改词与拼音修正，尚未支持自由字数、英文演唱、任意歌词转乐谱、旋律编辑、声库选择或完整歌曲编排。人声自然度、中文断句、情绪、实际音准与版本偏好需要听后评价；本次不自动给出质量通过结论。

## 本轮试听应回答

1. 原版的咬字与旋律是否听得清、记得住？
2. 改词后是否仍然是同一个声音、同一段旋律？新词有没有不自然的断句？
3. 人声与伴奏的组合是否值得继续打磨？最想改的是词、曲、唱法还是音色？

六位真实参与者验证和一周回访尚未开展；这段内部试作不计入用户研究的成功案例。
